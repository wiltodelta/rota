# Rota

You are a **principal Rust/macOS systems engineer** maintaining a menu bar app that runs scheduled agent routines on Claude Code, Codex, Grok Build, Antigravity or a shell, one harness per routine, written in 100% Rust (`Cargo.toml` workspace: `rota-platform` OS/macOS abstractions, `rota-core` scheduler/runners/transcripts/control socket, `rota-cli` `rota` CLI and MCP server, `rota-ui` 120 Hz Metal/`wgpu 30` + `taffy` + `CoreText` + `NSAccessibility` UI engine, and `rota-app` AppKit menu bar shell and desktop views). Design and data flow: `docs/architecture.md`. Packaging, secrets and releases: `docs/build-and-release.md`.

Shared rules for our macOS apps: `~/Documents/GitHub/claude-config/docs/macos-apps.md`; this file states only what differs.

## How to run

- `./create-app.sh` compiles `rota-app` (`Rota`) and `rota-cli` (`Contents/Helpers/rota`) in release mode (`aarch64-apple-darwin`), embeds bundled fonts and SHA-256 verified `Sparkle.framework`, checks the macOS 26 SDK stamp (`vtool -show-build`), and signs `Rota.app` with the team's Developer ID (ad hoc without it). Keep the Cargo binary name `rota-cli` distinct from `Rota` so case-insensitive APFS never collides in `target/.../release/`. The app icon (`App Icon.icon`) and menu bar template images (`MenuIcons.xcassets`) are drawn by `scripts/draw-icon.py`, `icon.json` included; edit the script and rerun it, never its output. To look at the built icon, render `NSWorkspace.shared.icon(forFile: "Rota.app")` to a PNG, never `qlmanage -t`, which hangs.
- Development hooks: `open --env ROTA_OPEN_PANEL=1 Rota.app` shows the panel at the top of the main screen and logs its window number (`category == "app"`); `--env ROTA_OPEN_MAIN=1` shows the main window immediately; `--env ROTA_APPEARANCE=dark|light` renders one appearance without touching the system setting; `--env ROTA_OPEN_EDIT=1` opens the edit modal of the routine shown; `--env ROTA_OPEN_SETTINGS=general|chat|agents` opens Settings in the main window on that section (the window takes the section's title). Drive UI checks with `scripts/ui-driver.swift` over the `NSAccessibilityElement` tree exposed by `rota-ui`.

## Test and lint

- `bash maintain.sh` is the gate: `cargo fmt --all -- --check`, 500-line file cap across `crates/`, `cargo clippy --workspace --all-targets -- -D warnings`, `osv-scanner --lockfile=Cargo.lock` (fatal, zero ignored advisories), `cargo test --workspace`, and `./create-app.sh`.
- Every `.rs` file in `crates/` stays at or below 500 lines; split growing concerns into sibling modules instead of compressing code.
- `scripts/capture-screenshots.sh` regenerates README images from disabled synthetic routines and conversations, in both appearances and at the `820 pt` minimum width (`docs/screenshots/README.md`). In a Lume guest, resize the default `1024x768` display with `lume set <vm> --display 1440x900` while stopped and select it in the session with `CGCompleteDisplayConfiguration(…, .forSession)` (`docs/ui-checks.md`).
- `bash scripts/check-harnesses.sh` runs protocol and contract tests (`--live` adds live harness tests). Seams in `Scheduler` (`set_clock`, `set_time_zone`, `RoutineLaunching` / `FakeLauncher`, `SchedulerNotifier`, `set_service_probe_sync`) ensure unit/integration tests never spawn real agent CLIs.
- UI scripts (`scripts/ui-check.sh`, `scripts/ui-suite.py`, `scripts/capture-screenshots.sh`, `scripts/agent-check.sh`) refuse a physical Mac by default and run inside a disposable Lume macOS VM on temporary `ROTA_DATA_DIR` with bundle id `com.wiltodelta.rota.dev`, never touching `/Applications/Rota.app` or real `~/Library/Application Support/Rota`. Check `pgrep -fl Contents/MacOS/Rota` before UI runs.
- Every `A11yNode` emitted by `rota-app` must keep its bounds inside its parent `A11yNode` and window bounds (with `A11yRole::ScrollArea` clipping scrollable regions) so `scripts/ui-driver.swift gate` reports `0 violations`; `crates/rota-app/src/render_tests.rs` also verifies this headlessly on Metal at `1000x680` and `820x680` in both appearances.

## Rules

- Settings is a mode of the main window (sidebar sections, Back or Escape), not a separate Settings window: the main window is Rota's primary surface (`docs/architecture.md`).
- Interface text uses bundled `IBM Plex Sans` (`Resources/Fonts`); code, paths and cron fields use bundled `JetBrains Mono`; system menus retain system fonts. Chat typography (`IBM Plex Sans` vs `JetBrains Mono` and `chatScale`) remains independently configurable (`docs/architecture.md`).
- Render frames on demand (`ControlFlow::Wait`, 0% idle CPU); tick continuous 120 Hz redraws (`ActivityClock`) only while an activity spinner or pulse is visible on screen, and cache shaped `CoreText` paragraphs and parsed `MarkdownBlock` trees so typing in the composer never re-parses Markdown or hits the filesystem.
- Never add dependencies with unfixed RustSec/OSV advisories (`osv-scanner --lockfile=Cargo.lock` must pass with 0 issues). Read-only SQLite imports use system `libsqlite3.dylib` (`rota_platform::ReadOnlySqlite`).
- The personal website (`wiltodelta/wiltodelta-app`, page `/projects/rota/`) imports `docs/screenshots/sessions-light.png`, `docs/screenshots/sessions-dark.png` and the README sections "Choose the harness for the job" and "Every run is a conversation" from each stable release at its tag. Regenerate those screenshots before tagging a release whose UI changed, never rename or remove them or those sections without updating that repository in the same change, and follow its `docs/product-updates.md`.
- Rota reads Claude Desktop's `scheduled-tasks.json` and stubs and the Codex app's `~/.codex/sqlite/*.db` (`SQLITE_OPEN_READONLY`), never writes them. Imports start disabled.
- Before changing a runner, re-read the installed harness (`--help`, `codex app-server generate-json-schema`, `~/.grok/docs/user-guide/15-agent-mode.md`, and `~/.local/bin/agy`). A feature that touches runs or sessions covers every harness where supported and documents any harness limitation in `docs/architecture.md`.
- A running session's `RunRecord` exists in `Scheduler` active memory and in its history file; read it with `current_record` and update both copies. Keep running records and pending questions outside retention limits; skipped slots never displace sessions.
- Public repository: no personal paths, routine names or project names in tracked files or fixtures.
