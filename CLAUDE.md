# Rota

You are a **principal Swift/macOS engineer** maintaining a menu bar app that runs scheduled agent routines on Claude Code, Codex, Grok Build, Antigravity or a shell, one harness per routine. SwiftPM; `RotaCore` holds the scheduler and runners, `Rota` the AppKit shell and SwiftUI views; the one dependency is Sparkle (`Updater`). Design and data flow: `docs/architecture.md`. Packaging, secrets and releases: `docs/build-and-release.md`.

Shared rules for our macOS apps: `~/Documents/GitHub/claude-config/docs/macos-apps.md`; this file states only what differs.

## How to run

- `./create-app.sh` builds and signs `Rota.app` with the team's Developer ID (ad hoc without it). The app icon (`App Icon.icon`) and the menu bar template images (`MenuIcons.xcassets`) are drawn by `scripts/draw-icon.py`, `icon.json` included; edit the script and rerun it, never its output. To look at the built icon, render `NSWorkspace.shared.icon(forFile: "Rota.app")` to a PNG, never `qlmanage -t`, which hangs.
- The status item often sits in a menu bar manager's hidden section on this Mac, so a scripted click does not open the panel. Development hooks: `open --env ROTA_OPEN_PANEL=1 Rota.app` shows the panel at the top of the main screen and logs its window number (`category == "app"`) for `screencapture -l`; `--env ROTA_APPEARANCE=dark|light` renders one appearance without touching the system setting; `--env ROTA_OPEN_EDIT=1` opens the edit sheet of the routine shown; `--env ROTA_OPEN_SETTINGS=1` opens Settings. System Events clicks and keystrokes did not reach the window here; drive it with `scripts/ui-driver.swift` (AX actions, and `key`, which posts a key event to Rota's pid and does reach it) and use these hooks to capture.

## Test and lint

- `scripts/capture-screenshots.sh` regenerates README images from disabled synthetic routines and conversations, in both appearances and at the minimum width. Its fixtures and native capture helper live beside it; the recipe and image inventory are in `docs/screenshots/README.md`. Detailed user-facing behavior is in `docs/user-guide.md`.
- `bash maintain.sh` is the gate. `swift test --filter` matches `Class/test`, not the file (`ProtocolTests.swift` holds several classes), and a mismatch only warns, so read the executed count. A JSON-RPC peer delivers replies on its run's queue (`callbackQueue`); a JSON value handed across queues goes in `UncheckedSendable`.
- `bash scripts/check-harnesses.sh` checks installed flags, schemas and catalogs without inference; `--live` adds native lifecycle, images, recovery, session MCP identity and questions. After changing a runner, follow `docs/harness-compatibility.md`, including actual CLI probes, explicit skips and cleanup. Recovery uses native state without a prompt; unknown state reserves the routine.
- Seams: `Scheduler.now`, `.calendar`, `.executable`, `.notifier`, and the `RoutineLaunching` launcher (`FakeLauncher` in `SchedulerTests` drives `RunEvents` by hand). Tests never spawn an agent.
- `ROTA_LIVE=1 swift test --filter LiveHarnessTests` runs Claude Code, Codex, Grok Build, Antigravity and Shell for real, sends a message mid-run, continues finished sessions, stops each harness, runs each agent on a chosen model and prints each log. It spends a little quota and leaves sessions behind: delete the `rota-live-*` Grok session folders, the Codex threads with a `rota-live-` cwd (their ids are in the first line of `~/.codex/sessions/<date>/rollout-*.jsonl`; delete each with `thread/delete` over `codex app-server` stdio, never in Codex's SQLite; a thread stopped moments ago answers `already has an active writer`, so retry a minute later), and the Claude transcripts under `~/.claude/projects/*rota-live*`. Antigravity-only tests match `LiveHarnessTests/testAntigravity`; without `ROTA_INTERACTIVE_TEST_DIR` (a folder Claude trusts directly or through its repository root) the background-task test quietly runs Claude's stream mode only; MCP registration uses a disposable home, and the optional tool-use test needs the isolated setup described in `docs/architecture.md`. Run it after touching a runner, in the background with a log.
- `scripts/ui-check.sh` uses synthetic Antigravity metadata shared with the catalog tests, checks its adjustable and fixed effort pickers and harness switching. (Add `--live` for a Codex session.) It is the end-to-end UI check: it drives the built app through the Accessibility API, checks each step, runs the layout gate on every capture, and saves both appearances at the minimum width to `/tmp/rota-ui-check` (empty, import, new routine with model pickers, running, finished, needs reply, routine, edit, menu bar panel, each settings tab; `--live` adds a running Codex session's composer). It runs the development build (`com.wiltodelta.rota.dev`, a non-`RELEASE` build) on a temporary `ROTA_DATA_DIR` and quits only that build by its path, so the installed Rota keeps running its routines; `scripts/ui-driver.swift` drives the dev bundle id unless `ROTA_BUNDLE_ID` names another. It reads this Mac's Claude Desktop and Codex for the import sheet, so its screenshots carry real routine names: keep them out of the repository. Never fire a real routine to test the scheduler.
- Many `ui-check.sh` frames capture an inactive window: default buttons and selections render gray, so compare with a key-window frame (traffic lights in colour) before calling it a defect. Help > Rota Help opens the README in the browser.
- Rerun `ui-check.sh` once before treating a menu bar panel relaunch failure (`no window` after `LSOpen` -600) or Settings General "outside visible screen" as a regression; both flake.
- `scripts/agent-check.sh` (after `./create-app.sh`) checks the `rota` command and `rota mcp` end to end on clean data, and has Claude Code, Codex and Grok Build each create a routine over MCP without touching their own MCP settings (Claude `--mcp-config`, Codex `-c mcp_servers.rota...`, Grok a project-scope config in the temp folder). Agent CLIs wait on stdin unless given `</dev/null`. It leaves one session per agent with a `rota-e2e-work` cwd; delete them as for the live tests. Never test Settings' Add buttons against the real configs from a dev build: they would point the agents at the repository's Rota.app.
- To try an interactive Claude run by hand, start it from a clean environment (`env -i HOME=… PATH=/usr/bin:/bin …`): a `claude` started inside another Claude session inherits `CLAUDE_CODE_CHILD_SESSION`, turns transcript saving off and leaves Rota nothing to read. It needs a folder Claude Code trusts, so it leaves its transcript in that project's `~/.claude/projects` folder: delete it after. Read the screen with `screen -S <name> -p 0 -X hardcopy <file>`; `screen -X` can hang while Claude inside retries an unreachable API, so bound it and end the session by pid.
- To check the scheduler live, write Shell routines into `routines.json` with a past or next-minute `nextFire` (catch-up, skip, scheduled slot) and launch the app; back up and remove that data after.
- Notification Center records the path of the first build that posts a notification as the app's source (`apps[…].src` in `~/Library/Group Containers/group.com.apple.usernoted/Library/Preferences/group.com.apple.usernoted.plist`) and draws the banner icon from there; a dev build in `~/Documents` (TCC-protected) or a deleted copy leaves every banner with the blank app icon. It is a system setting: report it, never edit it.
- Notification banners are not in the Accessibility tree, so they cannot be pressed from a script; read delivery from `/usr/bin/log show --predicate 'process == "usernoted"'` ("Presenting ... as banner").
- Check a change that affects layout, sizing or text fit at the minimum window width (`contentMinSize` in `RotaApp.swift`); the layout rules that width taught are in `docs/architecture.md`.

## Rules

- Interface text uses bundled IBM Plex Sans at native semantic sizes; SF Symbols and system-owned menus retain system fonts. Chat typography remains independently configurable (`docs/architecture.md`).
- The personal website (`wiltodelta/wiltodelta-app`, page `/projects/rota/`) imports `docs/screenshots/sessions-light.png`, `docs/screenshots/sessions-dark.png` and the README sections "Choose the harness for the job" and "Every run is a conversation" from each stable release at its tag. Regenerate those screenshots before tagging a release whose UI changed, never rename or remove them or those sections without updating that repository in the same change, and after publishing follow its `docs/product-updates.md`, "What product repositories owe the site".
- Rota reads Claude Desktop's `scheduled-tasks.json` and stubs and the Codex app's `~/.codex/sqlite/*.db` (`mode=ro`), never writes them: each app owns and rewrites its store. Imports start disabled.
- Before changing a runner, re-read the installed harness: `--help` (never probe with `claude <word>`: Claude has no such subcommands and sends the word as a prompt), `codex app-server generate-json-schema`, `~/.grok/docs/user-guide/15-agent-mode.md`, and `agy` for Antigravity, whose implementation and verification limits are in `docs/architecture.md`. Probe Grok's live ACP stream before handling an `_x.ai/` notification: its `updates.jsonl` archive names them differently.
- A feature that touches runs or sessions covers every harness, both Claude runners included: check each against those sources, implement it wherever the harness has the concept, and verify each runner you change. Where a harness lacks the concept or exposes no signal for it, record that with evidence under "Feature coverage across harnesses" in `docs/architecture.md`, which also holds the open gaps.
- Codex runs start the app-server daemon and Grok runs a leader process (`grok agent leader --no-exit-on-disconnect`); both stay up after the run, by those tools' design, with the folder and environment of whoever started them. A live test that starts them leaves them in its temporary folder: stop them after (`codex app-server daemon stop`, then end the `grok agent leader` process) once no client is connected.
- A running session's `RunRecord` exists twice, in `Scheduler.active` and in its history file, and the run's end saves the active copy. Read it with `Scheduler.current` and change both copies (as `setAttention` does), or the change is lost.
- Keep running records and their logs outside retention limits; skipped slots must never displace sessions. Historical model labels and continuations use the run's snapshot, never the routine's current options. Details: `docs/architecture.md`.
- Public repository: no personal paths, routine names or project names in tracked files or fixtures.
